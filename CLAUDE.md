## Rules for the Builder (structural, not vibes)

**R1 — NEVER WRITE AN INTERPRETATION BEFORE THE NUMBER EXISTS.** No output string that *characterizes* a result may be authored before the value it characterizes is computed. Interpretation strings are built from measured values at print time, or they do not exist. Verdicts must come from threshold-free statistics (AUC, permutation test, bootstrap CI) — if a verdict depends on a cutoff you chose yourself, you have tested nothing.
Twice-burned, both in one session:
- Phase 2 printed **"SCATTERED — investigate"** on a *correct* RPI calculation, because I scored a positions-based adjustment with a Pearson correlation against a 0.35 threshold I invented. Fixed with a permutation test: gap +1.92 positions, p=0.00005.
- Phase 3 printed **"lands close to his 2:1"** before the fit ran. It came out **1.00:1** and the sentence printed anyway.
**Why this rule outranks its apparent size:** Cody is the only reviewer and he reads the summaries, not the code. A confidently worded wrong interpretation is the highest-leverage error available to the Builder.

**R2 — COMPLETENESS RULE FOR THE CRAWL. Do not "optimise" this away.**
A **date** is authoritative only when (1) it is strictly in the past *and* (2) every game on it is final. A **game** is authoritative only when `game_state == 'F'`. Everything else stays refetchable.
On a finished season "skip anything already on disk" is correct and fast. On a **live** season it silently destroys data: a date fetched at 3pm caches the afternoon's partial slate as complete and the evening matches are never fetched again — unrecoverable, and it corrupts the game graph everything reconciles against. `games.jsonl` is append-only, so dedup is **final-beats-non-final, then last-wins** (`scripts/gamelog.py`); first-wins dedup would make a stale in-progress record permanently defeat its own correction. Guarded by `scripts/test_crawl_freshness.py` — verified to FAIL against the old behaviour.

**R7 — INDEPENDENCE BEATS DEPTH. Do not buy your way out of errors with effort.** Claude-app's evidence review (Builder_Logs / For_Cody, 2026-08-10) settles the question this project kept running into, and the literature matches our own 4-for-4 tally exactly:
- **Self-review adds ~nothing.** Cross-Model review measured Claude self-review at **91.4% → 91.4%** — 3 fixes, 3 regressions, +72% cost. Cross-Context review found the gain comes from **context separation, not extra passes**: repeated self-review did *not* beat single self-review (p=0.11), while a fresh no-context session did (F1 28.6 vs 24.6, p=0.008).
- **More reasoning does not question a false premise — it amplifies it.** No frontier model corrects >43% of false presuppositions; missing-premise questions produce 2–4× longer output that still misses the flaw. That is Saint Francis exactly.
- **Reasoning can crowd out verification:** *"the model spends too long reasoning internally, it begins to form assumptions about the environment rather than verifying them."* All three measurement bugs here were "didn't check" bugs.
- **Calibration can degrade with reasoning for the Claude family specifically** (Claude 3.7 Sonnet got *worse* calibrated with more reasoning).
**Operationally:** medium/high effort for mechanical crawling and transformation; reserve max for genuine design/analysis, and always pair it with an independent review because the producing agent rationalises its own frame. **Spend budget on mechanical invariants and a fresh-context reviewer, not on thinking harder.** Give the reviewer tools the builder didn't use. Treat any model's advertised "self-verification" as the exact signal this project distrusts.

**R6 — HOW TO VERIFY MOBILE CSS WITHOUT A PHONE.**
⚠ **DISCOVER THE BREAKPOINTS, DO NOT LIST THEM (added 2026-08-27, after it cost two false bug reports).** The lift below is only as good as the set of media queries it collects, and a hand-written list drifts exactly like the CI suite list did. A sweep matching `(390|560|600|640|760)px` **missed 700px**, where Intel's stacking rule lives — so the grid stayed two-column, chips spilled to 459px, and I reported horizontal overflow on Intel and clipped headings on the Ballot that **do not exist**. The page's real breakpoints are **560, 640, 700, 760, 860, 900, 1100**, and the correct sweep reads `conditionText.match(/max-width:\s*(\d+)px/)` and keeps every block whose value is ≥ the width being tested. With the full set, all 14 views are clean at 390px. **A negative result from an incomplete scanner is not a finding.**

Treating that as "mobile is unverifiable" cost five review cycles of Cody's time on four failed fixes. **Instead: lift the media block and inspect programmatically** via `javascript_tool` — walk `document.styleSheets`, find `CSSRule.MEDIA_RULE` whose `conditionText` matches, re-inject its `cssRules` as an unconditional `<style>`, then assert on the result (`getComputedStyle(tr).display === 'flex'`, visible cell count, `tr.scrollWidth > width` for overflow, distinct `getBoundingClientRect().top` values to prove wrapping). **R3 — STRENGTH ≠ RESUME.** Two ratings, two jobs, never merged. The **composite** (strength) answers "who would win a match" and drives the simulator.
